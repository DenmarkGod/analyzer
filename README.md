# Склад · Аналитика

Личный дашборд поверх JSON API МоегоСклада: KPI, графики оборота и денег,
алерты по остаткам, топ товаров и каналов продаж. Без сервера и без базы
данных — статический сайт на GitHub Pages, данные раз в несколько часов
обновляет GitHub Actions и кладёт в `data/latest.json`. Токен доступа
хранится только в секретах репозитория и никогда не попадает в браузер.

## Как это устроено

```
Расписание (cron) → GitHub Actions → scripts/sync.mjs → data/latest.json → git commit
                                                                                  │
                                                                                  ▼
                                                            GitHub Pages отдаёт index.html,
                                                            он читает data/latest.json и рисует графики
```

CORS тут не участвует вообще: браузер обращается только к файлам внутри
своего же сайта (`data/latest.json`), а к `api.moysklad.ru` ходит только
GitHub Actions — это серверный запрос, на который ограничения браузера
не распространяются.

## Установка

### 1. Токен доступа МоегоСклада

Проще всего завести **отдельного пользователя с ограниченными правами**
(только на чтение, без доступа к деньгам/CRM, если они вам не нужны) —
специально под эту интеграцию. Так безопаснее: если понадобится отозвать
доступ, не придётся ничего менять у себя.

Получить Bearer-токен можно запросом:

```
curl -X POST "https://api.moysklad.ru/api/remap/1.2/security/token" \
  -u "логин:пароль"
```

⚠️ Учтите: при генерации нового токена для того же пользователя МойСклад
отзывает предыдущие токены этого пользователя. Если вы потом получите
новый токен где-то ещё для того же логина — этот дашборд перестанет
работать, и токен в секрете репозитория нужно будет обновить.

### 2. Репозиторий

Создайте новый репозиторий на GitHub и загрузите туда все файлы из этого
проекта (можно просто перетащить папку через веб-интерфейс GitHub или
через `git push`).

### 3. Секрет с токеном

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**

- Имя: `MOYSKLAD_TOKEN`
- Значение: токен, полученный на шаге 1

### 4. Включить GitHub Pages

**Settings → Pages → Source**: выберите ветку `main` и папку `/ (root)`.
Через минуту сайт будет доступен по адресу вида
`https://<ваш-логин>.github.io/<репозиторий>/`.

### 5. Первый запуск синхронизации

По умолчанию workflow запускается по расписанию (`.github/workflows/sync.yml`,
каждые 6 часов) и его же можно запустить вручную:
**Actions → Sync MoySklad data → Run workflow**.

После первого успешного запуска в репозитории появится обновлённый
`data/latest.json`, и сайт покажет реальные данные вместо заглушки.

## Настройка под себя

- **Частота обновления** — строка `cron` в `.github/workflows/sync.yml`.
- **Глубина графиков и период прибыльности** — константы `TREND_DAYS` и
  `PROFIT_DAYS` в начале `scripts/sync.mjs`.
- **Размер топов и алертов** — константы `TOP_N`, `LOW_STOCK_LIMIT`,
  `STALE_STOCK_LIMIT` там же.

## ⚠️ Важно про приватность

GitHub Pages **всегда публикует сайт по открытой ссылке**, даже если сам
репозиторий приватный (приватная публикация — только на тарифе GitHub
Enterprise Cloud). То есть все цифры на этом дашборде — обороты, прибыль,
клиенты — доступны любому, кто узнает URL.

Что уже сделано для снижения риска:
- `robots.txt` запрещает индексацию поисковиками;
- `<meta name="robots" content="noindex, nofollow">` в `index.html`.

Это не делает сайт приватным — только менее заметным. Если данные
чувствительные, дополнительно стоит:
- выбрать репозиторию непредсказуемое имя (адрес сайта строится из него);
- никому не давать ссылку и не публиковать её нигде;
- при желании — перенести сайт на хостинг с настоящей авторизацией
  (например, Cloudflare Pages + Cloudflare Access), если понадобится
  реальный контроль доступа.

## Локальный запуск и отладка

```bash
MOYSKLAD_TOKEN=ваш_токен node scripts/sync.mjs   # соберёт data/latest.json локально
npx serve .                                       # или любой другой локальный http-сервер
```

Открывать `index.html` напрямую как файл (`file://`) не получится —
`fetch('data/latest.json')` работает только через http(s).

## Если раздел «Клиенты» пустой

Отчёт «Показатели контрагентов» доступен только при подключённой опции
CRM в тарифе и праве `viewCompanyCRM`. Если её нет — раздел просто
скрывается, остальной дашборд продолжает работать (см. `warnings` в
`data/latest.json` и в футере сайта — там видно, какие разделы
пропущены и почему).
